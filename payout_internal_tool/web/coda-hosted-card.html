Coda Hosted Card API — 0 → 100

Card Hosted Component flow · init + inquiry

This is the Card Hosted Component flow: your page stays put, Coda’s SDK collects card data, your backend only does init + status inquiry.

In our tool, the browser never calls Coda’s init/inquiry directly (CORS). It calls codaCardInit → proxies Coda init, and codaCardInquiry → proxies Coda inquiry. Same Coda APIs underneath.

0. Mental model (1 minute)

You (merchant)                  Coda
─────────────────               ────
1. Backend INIT  ─────────────► txnId + clientSecret
2. Frontend mounts card form with clientSecret
3. User pays; SDK talks to Coda (card data never hits your server)
4. Backend INQUIRY ────────────► success / pending / failed
Rule: Frontend “Pay succeeded” is not final. Inquiry is authoritative.

2. Step A — Initiate payment (POST …/init.json)

Sandbox: POST https://sandbox.codapayments.com/airtime/api/restful/v2.0/Payment/Component/init.json
Production: POST https://airtime.codapayments.com/airtime/api/restful/v2.0/Payment/Component/init.json
In PE Ops: POST …/codaCardInit with env, credentials, order fields.

Request (what Coda expects)

{
  "initRequest": {
    "country": 458,
    "payType": 421,
    "apiKey": "test_… or live_…",
    "projectId": 31,
    "orderId": "ord_unique_per_attempt",
    "currency": 458,
    "items": [
      { "code": "SKU001", "price": 1.0, "name": "Test Item" }
    ],
    "profile": {
      "entry": [{ "key": "user_id", "value": "ops-user-1" }]
    }
  }
}
  • Use numbers for country/currency/payType/projectId (as in Coda samples).
  • orderId = your unique ID (new every checkout attempt).
  • user_id in profile is required.

Expected success response

{
  "initResult": {
    "resultCode": 0,
    "resultDesc": "Success",
    "txnId": 7841…,
    "clientSecret": "eyJ…"
  }
}
FieldMeaningWhat you do
resultCode: 0Init OKContinue
txnIdCoda’s transaction idStore with your orderId (keep as string — too large for JS Number)
clientSecretShort-lived JWT for SDKPass to frontend once; do not cache/reuse

Init errors & root causes

What you seeLikely root cause
XML fault / NullPointerException / getRemoteServiceByRegion … nullInvalid country (e.g. 485), or key/project not mapped to that region
XML not allowedCountry/project not permitted for that key
HTTP 500 + XML, no initResultSame class — Coda failed before returning JSON
initResult.resultCode ≠ 0 (e.g. 103)Business rejection: channel/project/country/currency not enabled or misconfigured
txnId: 0Init failed; do not mount SDK
Empty / missing clientSecretCan’t mount Hosted Card; fix init first
Sandbox + live_ key (or prod + test_)Environment mismatch
Reused old clientSecretLater charge 400 — mint fresh per checkout

After success: backend returns to UI only { orderId, txnId, clientSecret, env } (never expose long-term apiKey in production apps).

3. Step B — Load SDK & mount card form

  1. Load https://js.codapayments.com/8.0.0/coda-card.min.js
  2. const codaCard = CodaCard()
  3. codaCard.components({ clientSecret, appearance })
  4. components.create('charge', { withCardHolderName, locale, … })
  5. chargeComponent.mount('#payment-form')
EventMeaning
userLoadedForm finished loading
readyStateChange(true)Fields valid → enable Pay
readyStateChange(false)Incomplete/invalid → keep Pay disabled

Mount errors

SymptomRoot cause

4. Step C — Submit payment (frontend → Coda directly)

chargeComponent.submit(); — only when readyStateChange === true. Card data goes to Coda only, not your backend.

EventSuccess pathFailure / nuance
shopperActionRequired(true)3DS modal will openShow “authenticating…”
shopperActionCompleted3DS doneResume processing UI
processingCard(true, …)SDK thinks charge acceptedStill not final — run inquiry
processingCard(false, errorMessage)—Declined / error; real reason often in charge body / inquiry

Submit errors

SymptomRoot cause
400 Bad Request on chargeEnv mismatch, expired clientSecret, wrong secret
processingCard(false)Card declined, auth failed, issuer reject
Stuck after 3DSWait for shopperActionCompleted then inquiry
User closes 3DSTreat as failed/pending → inquiry

5. Step D — Status inquiry (authoritative)

Sandbox: POST …/sandbox…/Payment/inquiryPaymentResult.json
Production: POST …/airtime…/Payment/inquiryPaymentResult.json
In PE Ops: POST …/codaCardInquiry 

{
  "inquiryPaymentRequest": {
    "apiKey": "same key as init",
    "country": 458,
    "projectId": "31",
    "txnId": "7841…",
    "needStatusFinal": "true"
  }
}

Use the txnId from init. Same env/key/country/project as init. Keep txnId as a string.

How to interpret

SignalMeaningAction
resultCode = 0 and/or profile.status = "success"PaidFulfill if final (isStatusFinal ideally true)
431 / 216 / 481 or status pendingNot finalPoll inquiry again with backoff
Other / status failedFailedDo not fulfill

6. End-to-end checklist

  1. Configure: sandbox or prod; matching test_/live_ key; projectId; card payType; valid country/currency (458/458).
  2. INIT → expect resultCode=0, store txnId, take clientSecret.
  3. Mount SDK with that clientSecret.
  4. Wait for readyStateChange(true) → enable Pay.
  5. submit() → handle 3DS events.
  6. On processingCard (or after 3DS) → INQUIRY by txnId.
  7. Fulfill only on inquiry success (ideally final).
  8. On decline/error → show retry; never fulfill.

7. How to learn it inside PE Ops

  1. Set env (sandbox/production) — key auto-fills.
  2. Confirm country/currency 458.
  3. Start payment session → debug should show Out to Coda: init.
  4. Fill card → Pay now.
  5. Check status → debug shows inquiry.
  6. Open request/response on each step to see real payloads.

Timeline direction legend: Out to Coda = backend → Coda (init / inquiry); App event = frontend SDK lifecycle.

8. Common “new to this API” traps

  • Treating SDK success as paid.
  • Reusing clientSecret.
  • Mixing sandbox/prod hosts and keys.
  • Wrong country code (485 vs 458).
  • Using channel 0/1 instead of real card payType.
  • Putting apiKey in the browser in a real customer app (OK only for this internal ops tool).
  • Parsing txnId as a JS Number (loses precision — keep as string).
